auto-reinit logic faithfully ported from the Makefile.

Purpose: Operators and CI can use `./run <command>` for every operation. The Makefile
stays intact (deleted in Phase 7); `./run` is additive in this phase.

Output: A single `run` file at repo root with executable bit committed to git.

    .planning/research/PITFALLS.md — C-1 (empty TF_STATE_BUCKET), C-2 (missing DEVBOX_USER guard), M-1 (bash 3.2), M-3 (cd persistence), M-5 (tf-ensure-init), m-2 (clean leaks auto.tfvars).
    .planning/research/STACK.md — bash version guard pattern, case dispatch pattern, variable naming.

  <action>
    Create file `run` (no .sh extension) at repo root. Structure per ARCHITECTURE.md internal layout:

    SECTION 1 — Shebang and strict mode:
    - Shebang: `#!/usr/bin/env bash`
    - `set -euo pipefail`
    - Bash version guard: check `BASH_VERSINFO[0] -lt 4`, print "ERROR: Bash 4+ required. macOS: brew install bash" to stderr, exit 1. This must be the first executable block (per RUN-06, STACK.md).

    SECTION 2 — REPO_ROOT anchor:
    - `REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` (per RUN-06, Pitfall M-3).

    SECTION 3 — Variable defaults (mirror Makefile lines 14-52 exactly):
    - `DEVBOX_USER="${DEVBOX_USER:-}"`
    - `TF_BIN="${TF_BIN:-tofu}"`
    - `TF_STATE_REGION="${TF_STATE_REGION:-us-east-1}"`
    - `TF_STATE_LOCK_TABLE="${TF_STATE_LOCK_TABLE:-devimage-tfstate-locks}"`
    - `INSTANCE_ID="${INSTANCE_ID:-}"`
    - `REGION="${REGION:-}"`
    - Do NOT derive TF_STATE_BUCKET or TF_STATE_KEY at startup — these are computed lazily.

    SECTION 4 — Guard functions:

    `_require_devbox_user()` (per RUN-03, RUN-08):
    - First check: if DEVBOX_USER is empty, print error with fix instructions (`DEVBOX_USER=jsmith ./run <command>` or `export DEVBOX_USER=jsmith`), exit 1.
    - Second check: validate format with pattern `^[a-z0-9][a-z0-9-]{0,30}[a-z0-9]$` using bash regex `[[ ! "$DEVBOX_USER" =~ ^[a-z0-9][a-z0-9-]{0,30}[a-z0-9]$ ]]`. Print "ERROR: DEVBOX_USER='...' is invalid. Must be lowercase alphanumeric + dash, 2-32 chars, no leading/trailing dash." to stderr, exit 1. (per RUN-08, matching CI regex in .gitlab-ci.yml deploy job).

    `_derive_tf_state_bucket()` (per RUN-04):
    - If TF_STATE_BUCKET is already set and non-empty, return (respect operator override).
    - Otherwise, run `aws sts get-caller-identity --query Account --output text` capturing output.
    - Guard: if the command fails or returns empty, or the composed bucket equals "devimage-tfstate-", print "ERROR: could not resolve AWS account ID via 'aws sts get-caller-identity'. Check your AWS credentials/profile, or set TF_STATE_BUCKET=... explicitly." to stderr, exit 1.
    - Set `TF_STATE_BUCKET="devimage-tfstate-${account_id}"`.
    - This function is called lazily, only by commands that need the backend (per Pitfall C-1, ARCHITECTURE.md anti-pattern "Eager TF_STATE_BUCKET resolution").

    `_tf_state_key()`:
    - Returns `users/${DEVBOX_USER}/devbox.tfstate`.

    `_tf_backend_args()`:
    - Calls `_derive_tf_state_bucket`.
    - Echoes the four `-backend-config` flags matching Makefile lines 49-52: bucket, key (from `_tf_state_key`), region (TF_STATE_REGION), dynamodb_table (TF_STATE_LOCK_TABLE).

    `_tf_var_args()`:
    - Echoes `-var "devbox_user=${DEVBOX_USER}" -var "key_name=${DEVBOX_USER}-devbox"` matching Makefile lines 46-47.

    SECTION 5 — Command functions (one per command, 20 total):

    Group A — Packer (no DEVBOX_USER guard needed):

    `cmd_packer_init()`: `(cd "$REPO_ROOT/packer" && packer init .)` — subshell cd pattern per Pitfall M-3.

    `cmd_validate()`: call `cmd_packer_init` first (matches Makefile prerequisite), then `(cd "$REPO_ROOT/packer" && packer validate .)` then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" validate)`.

    `cmd_build()`: call `cmd_packer_init` first, then `(cd "$REPO_ROOT/packer" && packer build .)`.

    `cmd_fmt()`: `(cd "$REPO_ROOT/packer" && packer fmt .)` then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" fmt)` then `echo "Format complete"`.

    Group B — Terraform (need DEVBOX_USER + backend guards):

    `cmd_tf_ensure_init()` (per RUN-05, Pitfall M-5):
    - Call `_require_devbox_user`.
    - Compute desired key via `_tf_state_key`.
    - Read cached key: `jq -r '.backend.config.key // empty' "$REPO_ROOT/terraform/.terraform/terraform.tfstate" 2>/dev/null || true`.
    - If cached key differs from desired key, print "[tf-ensure-init] backend cache mismatch (cached='$cached_key', want='$desired_key'); reinitializing..." and call `cmd_tf_reinit`.

    `cmd_tf_init()`:
    - Call `_require_devbox_user`.
    - Call `_derive_tf_state_bucket` (includes the empty-bucket guard per RUN-04).
    - Run `(cd "$REPO_ROOT/terraform" && "$TF_BIN" init $(_tf_backend_args))`.

    `cmd_tf_reinit()`:
    - Call `_require_devbox_user`.
    - Call `_derive_tf_state_bucket`.
    - Run `(cd "$REPO_ROOT/terraform" && "$TF_BIN" init -reconfigure $(_tf_backend_args))`.

    `cmd_tf_plan()`: call `cmd_tf_ensure_init`, then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" plan $(_tf_var_args))`.

    `cmd_tf_apply()`: call `cmd_tf_ensure_init`, then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" apply $(_tf_var_args))`.

    `cmd_tf_auto_apply()`: call `cmd_tf_ensure_init`, then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" apply -auto-approve $(_tf_var_args))`.

    `cmd_tf_destroy()`: call `cmd_tf_ensure_init`, then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" destroy $(_tf_var_args))`.

    `cmd_tf_auto_destroy()`: call `cmd_tf_ensure_init`, then `(cd "$REPO_ROOT/terraform" && "$TF_BIN" destroy -auto-approve $(_tf_var_args))`.

    Group C — Lifecycle (need tf-ensure-init; delegate to scripts):

    `cmd_start()`: call `cmd_tf_ensure_init`, then run `DEVBOX_USER="$DEVBOX_USER" INSTANCE_ID="$INSTANCE_ID" REGION="$REGION" "$REPO_ROOT/scripts/devbox-start.sh" "$@"`.

    `cmd_stop()`: same pattern, delegate to `devbox-stop.sh`.

    `cmd_status()`: same pattern, delegate to `devbox-status.sh`.

    Group D — SSM:

    `cmd_devbox_ssm()`: call `cmd_tf_ensure_init`, then delegate to `"$REPO_ROOT/scripts/devbox-ssm.sh" "$@"` with env vars.

    `cmd_devbox_port_forward()` (per Pitfall m-3):
    - Call `_require_devbox_user` (NOT tf-ensure-init — matches Makefile which only has `_require-devbox-user` prerequisite).
    - Check `command -v session-manager-plugin` — if missing, print install instructions to stderr, exit 1.
    - Resolve INSTANCE_ID and REGION via `(cd "$REPO_ROOT/terraform" && "$TF_BIN" output -raw instance_id)` and `(cd "$REPO_ROOT/terraform" && "$TF_BIN" output -raw aws_region)`.
    - Print forwarding info messages.
    - `exec aws ssm start-session` with the SSM port-forwarding parameters matching Makefile lines 187-191. The `exec` MUST be the final statement — no code after it (per Pitfall m-3).

    Group E — Secrets:

    `cmd_secrets_show()`:
    - Call `_require_devbox_user` (NOT tf-ensure-init — matches Makefile).
    - Resolve code-server password from SSM: `aws ssm get-parameter --name "/devbox/${DEVBOX_USER}/code-server-password" --with-decryption --query 'Parameter.Value' --output text`. If fails, print error with "Run './run build' first" hint (note: use `./run build` not `make build`).
    - Resolve VNC password similarly.
    - Print both passwords matching Makefile output format.

    Group F — Cleanup:

    `cmd_clean()`:
    - `rm -rf "$REPO_ROOT/packer/packer_cache"`
    - `rm -rf "$REPO_ROOT/terraform/.terraform"`
    - `rm -f "$REPO_ROOT/users/"*.auto.tfvars` (per Pitfall m-2 — do NOT forget the auto.tfvars).

    Group G — Help:

    `cmd_help()` (per RUN-02):
    - Print usage header: `Usage: ./run <command> [DEVBOX_USER=username]`
    - Print grouped command listing matching the six groups in the Makefile help target exactly:
      AMI (packer-init, validate, build, fmt),
      Terraform/OpenTofu (tf-init, tf-reinit, tf-plan, tf-apply, tf-auto-apply, tf-destroy, tf-auto-destroy),
      Instance lifecycle (start, stop, status),
      SSM access (devbox-ssm, devbox-port-forward),
      Secrets (secrets-show),
      Cleanup (clean).
    - Command descriptions must match Makefile help output. Update syntax examples from `make <target>` to `./run <command>` where they appear.

    SECTION 6 — Main dispatcher:
    - `COMMAND="${1:-help}"`
    - `shift || true`
    - case statement mapping all 20 command names to their functions, passing `"$@"` for commands that accept extra args.
    - Hyphenated names in case branches: `tf-init)`, `tf-reinit)`, `tf-plan)`, `tf-apply)`, `tf-auto-apply)`, `tf-destroy)`, `tf-auto-destroy)`, `devbox-ssm)`, `devbox-port-forward)`, `secrets-show)`, `packer-init)`.
    - `help|--help|-h)` maps to `cmd_help`.
    - Default `*)` branch: print "ERROR: Unknown command '${COMMAND}'. Run './run help' for usage." to stderr, exit 1.
    - Wrap in `main() { ... }` and call `main "$@"` at bottom of file.

    IMPORTANT constraints:
    - Do NOT source scripts/_common.sh from ./run. The run script is a standalone dispatcher. Lifecycle scripts source _common.sh themselves.
    - Use subshell `(cd dir && cmd)` for every directory change — never bare `cd` (per RUN-06, Pitfall M-3).
    - All variable expansions double-quoted (per codebase convention).
    - No `function` keyword — use POSIX `name() { ... }` style (per codebase convention).
    - No bash 4+ features that would fail on bash 3.2 (but note the version guard exits before reaching them — still, prefer portable patterns where trivial; the regex in `_require_devbox_user` is bash 3+ compatible via `=~`).
    - Error messages follow existing convention: "ERROR: <what>." on first line, "       <fix>" on subsequent lines, all to stderr.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env -> ./run | DEVBOX_USER from environment is untrusted input; must be validated before use in S3 keys, SSM paths, and shell commands |
| ./run -> AWS API | TF_STATE_BUCKET derivation crosses from local script to AWS STS; credential absence must not produce a valid-looking bucket name |
| ./run -> tofu/packer | Command arguments are constructed from validated DEVBOX_USER; no eval or unquoted expansion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | DEVBOX_USER in TF_STATE_KEY | mitigate | validate format with regex `^[a-z0-9][a-z0-9-]{0,30}[a-z0-9]$` in `_require_devbox_user` before any use in paths or commands |
| T-05-02 | Tampering | case dispatch | mitigate | use explicit case branches (not eval/compgen) so only listed commands execute |
| T-05-03 | Information Disclosure | TF_STATE_BUCKET in error messages | accept | bucket name contains account ID which is already visible in TF_STATE_BUCKET env var and CI logs — low sensitivity per existing threat model T-be1-05 |
| T-05-04 | Denial of Service | empty TF_STATE_BUCKET passed to tofu init | mitigate | `_derive_tf_state_bucket` fails fast if account ID is empty or derivation produces "devimage-tfstate-" |
| T-05-05 | Elevation of Privilege | DEVBOX_USER injection into shell commands | mitigate | DEVBOX_USER is regex-validated (no spaces, semicolons, quotes possible); all uses are double-quoted; no eval |
</threat_model>
