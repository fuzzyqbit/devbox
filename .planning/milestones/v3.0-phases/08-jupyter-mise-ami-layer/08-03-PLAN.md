<objective>
Extend the existing `secrets` role to handle the Jupyter password end to end: generate a per-build random cleartext (in-memory, `no_log`), publish it to SSM SecureString at `/devbox/{{ devbox_user }}/jupyter-password`, and extend the boot oneshot to fetch the cleartext at first boot, hash it via the `/opt/jupyter` venv, write only `c.PasswordIdentityProvider.hashed_password` into `~/.jupyter/jupyter_server_config.py`, and add `jupyter.service` to the restart loop + `Before=` ordering (JUP-03, JUP-04).

Purpose: Reuses the proven code-server/VNC secret mechanism so Jupyter's password never touches the AMI filesystem or git, and is correctly hashed (with a FIPS-safe sha256 fallback) at runtime.
Output: extended `secrets` role defaults, generate.yml, publish.yml, and both bootstrap templates.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ansible build host → SSM | Cleartext password generated in-memory at bake, written to SSM SecureString over the API |
| SSM → instance (boot) | Instance profile fetches the SecureString via IMDSv2 + `--with-decryption` |
| Boot script → ~/.jupyter config | Hashed (never cleartext) value written to a 0600 file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-07 | Information Disclosure | jupyter_password leaking into Ansible logs / AMI | mitigate | `no_log: true` on every set_fact/assert/ssm_parameter touching `jupyter_password`; cleartext lives only in-memory + SSM SecureString; never written to disk at bake. |
| T-08-08 | Information Disclosure | Hashed password file readable by other users | mitigate | `~/.jupyter/jupyter_server_config.py` written mode 0600, dir 0700, owned ec2-user; only a hash (not cleartext) is stored. |
| T-08-09 | Tampering / DoS | `.json` config silently overriding the `.py` password | mitigate | Boot script writes only `.py`, never `.json`, and embeds a comment warning; verify gate asserts no `.json` write. |
| T-08-10 | Denial of Service | argon2 failing under FIPS, blocking boot | mitigate | Unconditional sha256 fallback (`algorithm='sha256'`) on hash failure; empty-hash guard exits non-zero rather than writing an open config. |
| T-08-11 | Elevation / open access | Jupyter starting before the password config is written | mitigate | Unit `Before=...jupyter.service` + Plan 02's `After=...bootstrap.service`; marker written before restart so the oneshot is idempotent. |
</threat_model>
