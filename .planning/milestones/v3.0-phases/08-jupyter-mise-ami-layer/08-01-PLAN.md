<objective>
Create the new `mise` Ansible role: download the version-pinned, checksum-verified `mise` binary into the baked AMI and install a system-wide bash activation hook at `/etc/profile.d/mise.sh`. Zero managed tools, no committed `.mise.toml`, existing per-language roles untouched (MISE-03).

Purpose: Gives every login shell on the devbox a working `mise` version manager without coupling it to the existing python/golang/rust/java/node bake layers.
Output: `ansible/roles/mise/defaults/main.yml` + `ansible/roles/mise/tasks/main.yml`, with the real upstream SHA-256 checksum pinned in defaults.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases → AMI bake | Untrusted upstream artifact (mise binary) crosses into the baked image |
| /etc/profile.d → every login shell | The activation snippet runs `eval` in every operator login shell |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | mise binary download (`get_url`) | mitigate | Pin explicit `mise_version` + verify `checksum: "sha256:{{ mise_checksum_sha256 }}"`; checksum taken from upstream SHASUMS256.txt. No `latest` redirect. |
| T-08-02 | Tampering | `eval "$(mise activate bash)"` in /etc/profile.d | accept | mise binary is checksum-pinned and from the official `jdx` org; `eval` runs the verified binary's own activation output, same trust model as the existing golang/certs profile.d files. |
| T-08-SC | Tampering | mise install (GitHub Releases artifact) | mitigate | slopcheck unavailable → `[ASSUMED]`; Task 0 blocking-human checkpoint verifies official `jdx` org + real SHASUMS256.txt value before the download task lands. Not auto-approvable. |
</threat_model>
