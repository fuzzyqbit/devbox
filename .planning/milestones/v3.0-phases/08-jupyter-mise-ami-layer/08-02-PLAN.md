<objective>
Create the new `jupyter` Ansible role: build an isolated `/opt/jupyter` virtualenv, install pinned JupyterLab + ipykernel, register the Python-3 kernel into the venv prefix, generate a self-signed TLS cert at `/etc/jupyter`, and install + enable a systemd unit that serves JupyterLab over HTTPS on `0.0.0.0:8888`. The bake-time config carries NO password — the boot oneshot (Plan 03) injects the hashed password at first boot (JUP-04).

Purpose: Delivers the "code-server, but for notebooks" service surface (D-01..D-04) as a hardened, isolated systemd service in the AMI.
Output: `ansible/roles/jupyter/{defaults,tasks,handlers}/main.yml` + `templates/jupyter.service.j2`.
</objective>

    3. "Install JupyterLab + ipykernel into venv" — `command` `{{ jupyter_venv_path }}/bin/pip install jupyterlab=={{ jupyterlab_version }} ipykernel=={{ ipykernel_version }}` (invoke the venv pip directly, not the `pip` module). Add `args.creates: {{ jupyter_venv_path }}/bin/jupyter` for idempotency.
    4. "Register Python kernel into venv prefix" — `command` `{{ jupyter_venv_path }}/bin/python3 -m ipykernel install --prefix {{ jupyter_venv_path }} --name python3 --display-name "Python 3"` (use `--prefix`, NEVER `--user`; RESEARCH Pitfall 2). Add `args.creates` on the kernelspec dir.

Cert dir + "Generate self-signed TLS cert for Jupyter" — openssl `req -x509 -nodes -newkey rsa:2048 -keyout {{ jupyter_cert_dir }}/jupyter-key.pem -out {{ jupyter_cert_dir }}/jupyter-cert.pem -days 3650 -subj '/CN=devbox'` with `args.creates` on the cert; then a perms loop setting cert `0644` and key `0640`, both `owner: root group: {{ dev_user }}` (mirror desktop/noVNC).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI → /opt/jupyter venv | Untrusted upstream packages installed into the baked image |
| Network → jupyter.service :8888 | Authenticated web service surface (CIDR-gated SG added in Phase 9) |
| AMI snapshot at rest | Anything written to disk at bake time ships in the image |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Information Disclosure | Jupyter running tokenless/open | mitigate | Auth enforced via `c.PasswordIdentityProvider.hashed_password` (written by Plan 03 boot oneshot); unit passes no token-disabling flag; service ordered `After=devbox-secrets-bootstrap.service` so it never starts before the password config exists. |
| T-08-04 | Information Disclosure | Cleartext/hash password baked into AMI | mitigate | Jupyter role writes NO config file and NO password at bake time; verify gate asserts absence of `hashed_password` in role files. |
| T-08-05 | Information Disclosure | TLS private key `/etc/jupyter/jupyter-key.pem` readable | mitigate | Key mode `0640` root:ec2-user (mirrors noVNC); cert `0644`. |
| T-08-06 | Spoofing | Self-signed cert (MITM) | accept | Same posture as code-server/noVNC; access is CIDR-gated by the SG rule added in Phase 9. Acceptable per project network posture. |
| T-08-SC | Tampering | pip installs (jupyterlab/ipykernel) | mitigate | Versions pinned (`==`); packages confirmed official Jupyter/IPython org; Task 0 blocking-human checkpoint precedes install. Not auto-approvable. |
</threat_model>
