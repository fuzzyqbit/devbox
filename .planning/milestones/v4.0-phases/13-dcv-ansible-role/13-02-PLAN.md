<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bake assert → AMI ship gate | The assert is the boundary between a verified AMI and a green-but-broken one; a missing assert lets a broken DCV ship |
| dcv role → hardening role (ordering) | dcv MUST run before hardening (which flips SELinux enforcing + FIPS + reboots); wrong order re-opens what hardening locks / breaks the relabel timing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-08 | Tampering | role ordering vs. hardening-last invariant | mitigate | `- role: dcv` inserted strictly before `- role: hardening`; the hardening-last grep-gate (CLAUDE.md §8, enforced by pre-commit + CI) prints 1; Task 1 verify asserts it. Inserting after hardening re-opens the locked-down baseline. |
| T-13-09 | Repudiation/DoS | green-but-broken AMI (missing cert / QUIC off / disabled service) | mitigate | RDP-13-grade bake assert fails the bake loudly on any missing binary/conf-key/cert/SAN/perm/enablement — the artifact-level proof that a silent regression cannot ship. |
| T-13-10 | Spoofing | non-FIPS / CN-only cert silently shipped | mitigate | The bake assert reads the actual cert (openssl x509) and fails if no subjectAltName=DNS:devbox — proves the FIPS-strict handshake cert is in place, not just that a file exists. |
| T-13-11 | EoP | passwordless desktop (authentication=none) slips into dcv.conf | mitigate | The bake assert slurps dcv.conf and fails if authentication="system" is absent OR authentication="none" is present (security gate against the passwordless-desktop EoP). |
| T-13-SC | Tampering | npm/pip/cargo installs | n/a | This plan only wires + asserts; no package installs (those are 13-01, covered by T-13-02). No registry packages → no slopcheck checkpoint required. |
</threat_model>
