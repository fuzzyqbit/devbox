<spal_facts>
Authoritative SPAL mechanics (AWS docs, fetched 2026-07-07 —
https://docs.aws.amazon.com/linux/al2023/ug/configure-spal-repository.html and .../spal.html):

- ENABLE: `sudo dnf install spal-release`. This Amazon-signed package (in the AL2023 core
  repo) installs `/etc/yum.repos.d/amazonlinux-spal.repo` AND imports the SPAL GPG keys.
  This IS the canonical way to get the "SPAL repo file under /etc/yum.repos.d/" the CONTEXT
  locked decision calls for — use it INSTEAD of hand-writing a .repo file (a hand-hardcoded
  baseurl/GPG-key would drift and bypass the Amazon-signed release package). GPG check stays
  ON for every dnf install (no --nogpgcheck; matches CLAUDE.md §8 airgap posture).
- VERSION FLOOR: SPAL requires AL2023 `system-release` >= 2023.9.20251117. Older AMIs have no
  `spal-release` package -> `dnf install spal-release` fails cryptically. Assert the floor
  FIRST with a readable fail_msg (mirror the Phase 10 leading-assert pattern).
- VERSIONED REPO: SPAL content is pinned to the `system-release` version (deterministic
  upgrades). Combined with an explicit `xrdp-<ver>` pin this is the closest analog to the
  repo's SHA-pin invariant — exactly as the CONTEXT decision states.
- SUPPORT CAVEAT (verbatim from AWS): SPAL packages are NOT covered by AWS Support Plans,
  are provided as-is from upstream EPEL9, will NOT receive AWS CVE security tracking, and get
  security patches only from upstream EPEL9 when available. This is the CLAUDE.md caveat (XRDP-05).
- xrdp/xorgxrdp are EPEL9 packages; SPAL is an EPEL9 rebuild, so both are expected present.
  CONFIRM at exec: `dnf list --repo=amazonlinux-spal xrdp xorgxrdp`.
</spal_facts>
