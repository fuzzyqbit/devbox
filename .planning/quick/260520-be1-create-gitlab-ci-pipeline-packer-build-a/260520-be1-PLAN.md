<objective>
Add a `.gitlab-ci.yml` to the repository root that delivers an end-to-end GitLab
CI/CD pipeline for this project, alongside (not replacing) the existing GitHub
Actions workflows in `.github/workflows/`. The pipeline has three stages:

1. **validate** — the same eight parallel gates as `.github/workflows/ci.yml`:
   tofu fmt-check, tofu validate, packer validate, ansible-lint,
   ansible-playbook --syntax-check, shellcheck, Checkov (`--hard-fail-on HIGH`
   via `.checkov.yaml`), and the seven Phase-3 + CI-hardening `grep-gates`.
2. **build** — `packer build` produces an AMI and emits a build→deploy
   handoff file `users/${DEVBOX_USER}.auto.tfvars` (containing the literal
   AMI ID) as a GitLab artifact.
3. **deploy** — `tofu init` + `tofu apply` consumes the artifact and
   provisions the EC2 instance. `when: manual` and gated on a protected
   branch since this provisions real AWS resources.

AWS authentication uses GitLab OIDC federation (`id_tokens:` →
`sts assume-role-with-web-identity`). No static IAM keys touch CI variables.

Purpose: Give operators a GitLab-first execution path that preserves every
security invariant the GitHub Actions baseline already enforces — SHA-pinned
images (Docker digest equivalents for GitLab job images), parallel gate jobs,
hard-fail on HIGH Checkov findings, lockfile-readonly tofu init, and the seven
grep-gates that pin Phase-3 reproducibility.

Output: A single, self-contained `.gitlab-ci.yml` at the repo root.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitLab CI runner → AWS | Untrusted JWT (id_token) crosses into AWS STS via assume-role-with-web-identity. The IAM role's trust policy is the gate. |
| Container image registry → CI runner | Pulled Docker images execute as the job. Compromise of an upstream image = arbitrary code in CI with our OIDC token reach. |
| Packer build → AWS account | Packer launches a real EC2, runs Ansible on it, snapshots an AMI. Ansible playbook content executes with the build-instance's IAM profile. |
| Tofu apply → AWS account | `tofu apply` mutates real infrastructure with full role permissions. |
| `.gitlab-ci.yml` source → CI engine | Any contributor with merge access to the default branch can author CI code. Self-hosted GitLab admins are the implicit root of trust. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-be1-01 | Spoofing | OIDC token (GITLAB_OIDC_TOKEN) | mitigate | IAM trust policy MUST scope `sub` (project_path + ref_type + ref) AND `aud` (gitlab instance URL). Documented inline in the header comment + IMAGES.txt. Without this, any GitLab project on the same instance could assume the role. |
| T-be1-02 | Tampering | Container image (supply-chain) | mitigate | Every `image:` digest-pinned to `@sha256:...`. CLAUDE.md §8 maps the GH-Action SHA-pin policy to this. Grep-gate invariant #8 fails the pipeline if anyone introduces an unpinned image. |
| T-be1-03 | Tampering | `terraform/.terraform.lock.hcl` drift | mitigate | `tofu init -lockfile=readonly` in both validate:tofu-validate and deploy:tofu-apply. Matches .github/workflows/ci.yml line 76. Any provider drift fails init loudly. |
| T-be1-04 | Repudiation | Who triggered the deploy? | mitigate | `when: manual` + protected branch + GitLab's built-in audit log (records which user clicked "play"). `--role-session-name "gl-${CI_PROJECT_ID}-${CI_PIPELINE_ID}-${CI_JOB_ID}"` carries the pipeline/job ID into CloudTrail. |
| T-be1-05 | Information Disclosure | AWS_ROLE_ARN / TF_STATE_BUCKET in CI logs | mitigate | Configured as GitLab masked + protected variables — admin sets them out-of-band. Documented in IMAGES.txt and the file header; never committed in YAML. | T-be1-06 | Information Disclosure | Per-operator passwords in tfplan artifact | accept | `terraform/tfplan` is uploaded as `when: on_failure` only, expires in 1 month. AWS secrets live in SSM Parameter Store (Phase 1 SEC-03), not in tfstate or tfplan. Risk: a tfplan failure during regeneration could surface SSM ARNs (not values). Acceptable given the alternative (no plan available for post-mortem). |
| T-be1-07 | Denial of Service | Runaway packer build | accept | Packer builds are bounded by the runner's job timeout (GitLab default 1h; project-configurable). Cost cap is the AWS account's normal EC2 quota. Not pipeline-specific. |
