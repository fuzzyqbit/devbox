# Required GitLab CI/CD variables (set by repo admin — NOT in YAML)
# ====================================================================
#
# Path in GitLab UI: Settings -> CI/CD -> Variables
#
#   AWS_ROLE_ARN     (masked, protected)
#                    e.g. arn:aws:iam::123456789012:role/gitlab-devbox-ci
#                    The IAM role .gitlab-ci.yml assumes via OIDC.
#   AWS_REGION       (protected)
#                    e.g. us-east-1
#                    Threads into packer build (-var aws_region=) and
#                    tofu's AWS provider.
#   DEVBOX_USER      (protected)
#                    e.g. jsmith
#                    Per-operator identity. Routes the tfstate key, the
#                    SSH key name, the SG name prefix, and the SSM
#                    parameter prefix. Matches Makefile §14 — NO whoami
#                    default; pipeline fails loud if unset.
#   TF_STATE_BUCKET  (protected)
#                    e.g. devimage-tfstate-123456789012
#                    S3 backend bucket for the tofu state file.
#   AWS_OIDC_AUD     (protected; OPTIONAL)
#                    Default: https://gitlab.com
#                    Override for self-hosted GitLab instances. The IAM
#                    trust-policy `aud` condition MUST match this exactly.
#
# All five MUST be marked "Protected" so they only flow into pipelines
# triggered against protected branches (i.e. the default branch). AWS_ROLE_ARN
# additionally MUST be marked "Masked" so it is redacted from job logs.


# ====================================================================
# Required IAM role trust policy
# ====================================================================
#
# Paste this into the trust policy of the AWS IAM role that AWS_ROLE_ARN
# resolves to. The OIDC provider must be created first via:
#
#   aws iam create-open-id-connect-provider \
#     --url https://gitlab.com \
#     --client-id-list https://gitlab.com \
#     --thumbprint-list <gitlab.com TLS thumbprint>
#
# Trust-policy JSON (replace <ACCT>, <group>, <project> with literal values):
#
# {
#   "Version": "2012-10-17",
#   "Statement": [{
#     "Effect": "Allow",
#     "Principal": { "Federated": "arn:aws:iam::<ACCT>:oidc-provider/gitlab.com" },
#     "Action": "sts:AssumeRoleWithWebIdentity",
#     "Condition": {
#       "StringEquals": { "gitlab.com:aud": "https://gitlab.com" },
#       "StringLike":   { "gitlab.com:sub": "project_path:<group>/<project>:ref_type:branch:ref:main" }
#     }
#   }]
# }
#
# Threat-model linkage (T-be1-01, T-be1-10):
#  - `aud` MUST match the value the pipeline requests in `id_tokens:` (default
#    "https://gitlab.com"). Without this, any GitLab project on the same
#    instance can request a token and assume the role.
#  - `sub` MUST narrow to the specific group/project AND a protected branch.
#    Wildcarding `sub` (e.g. `project_path:*`) re-opens the boundary.
#
# Role permissions policy (NOT in trust policy — attached separately):
#   - ec2:* (or scoped to RunInstances + Describe* + ModifyInstanceAttribute +
#     StopInstances + StartInstances + CreateSecurityGroup + AuthorizeSecurityGroupIngress)
#   - iam:PassRole on the EC2 instance profile only
#   - s3:GetObject / PutObject / DeleteObject on the tfstate bucket only
#   - dynamodb:GetItem / PutItem / DeleteItem on the lock table only
#   - ssm:PutParameter / GetParameter / DeleteParameter on /devbox/* only
#   - kms:Decrypt scoped via kms:ViaService = ssm.<region>.amazonaws.com
