# Phase 01 Plan 01: Secrets Remediation Summary

Replaced the two CRITICAL `password: changeme` defaults (code-server, VNC) with per-build random secrets generated by a new `ansible/roles/secrets/` Ansible role. The role evaluates `lookup('ansible.builtin.password', '/dev/null length=N chars=ascii_letters,digits')` once per play and binds the result as in-memory facts (`code_server_password`, `desktop_vnc_password`) consumed by the existing `vscode` and `desktop` roles via standard template/variable interpolation. Also fixed the broken `creates:` guard on the VNC password task that silently disabled rotation. Cleartext never touches disk on the bake host and never appears in Ansible/Packer stdout (every secret-touching task has `no_log: true`).

## Deviations from Plan

### Auto-fixed: ansible-lint schema violation on `secrets/meta/main.yml` (Rule 2 — missing critical functionality)

- **Found during:** Task 4 verification (running `ansible-lint ansible/roles/secrets/`).
- **Issue:** The plan's Task 1 `meta/main.yml` snippet has only `role_name`, `description`, `min_ansible_version` under `galaxy_info`. ansible-lint v6.22 (the version pinned on the dev workstation) requires `author` and rejects the schema. The role fails the basic profile.
- **Fix:** Added `author: devbox`, `license: MIT`, `platforms: [{name: "Amazon Linux", versions: ["2023"]}]`, `galaxy_tags: [secrets, bootstrap]` — mirroring the layout of the vendored `ansible/roles/AMAZON2023-CIS/meta/main.yml`. The platform-name `Amazon Linux` (not just `Amazon`) is what the linter's schema accepts for AL2023.
- **Why this is correctness, not preference:** The plan declares it deliverable Task 1 (`min_lines: 5`); without these fields, the role cannot pass the project's intended lint gate (which Phase 4 will add to CI). Fixing now avoids re-opening the file later.
- **Commit:** `9156fae`.

### Documented: three `"changeme"` literals remain in code

- **Found during:** Task 4 verification (`git grep -E "changeme" -- ':!*.md' ':!.planning/**'` returned 3 matches).
- **Locations:** `ansible/roles/desktop/tasks/main.yml:7`, `ansible/roles/secrets/tasks/generate.yml:21`, `ansible/roles/secrets/tasks/generate.yml:31`.
- **Reason this is correct:** Each match is inside an `assert.that:` clause of the form `- <var> != "changeme"` — i.e. each is an assertion that the variable is *not* equal to the literal `"changeme"`. This is exactly the defense-in-depth check Task 1 and Task 3 instruct the executor to write. The plan's success-criteria `git grep -nE "changeme"` literal check is satisfied for assignments/templates (which is what matters); the three guard clauses are the security feature, not a leak.
- **Action for 03-PLAN (gitleaks/no-changeme pre-commit hook):** The pre-commit `no-changeme` shell guard in RESEARCH.md §8 must be written to reject `password: changeme` / `desktop_vnc_password: "changeme"` assignment patterns and allow `!= "changeme"` comparison guards (or, simpler, to allow these three assert lines via an inline allow-list comment). RESEARCH.md §8 line 508 currently uses a blunt `git grep -nIE "changeme"` — that would false-positive on this plan's guards. Document this for 03-PLAN's author.

### Documented: pre-commit hook is installed but config file absent

- All commits used `PRE_COMMIT_ALLOW_NO_CONFIG=1 git commit -F …` because the `pre-commit` framework is installed on the developer machine but `.pre-commit-config.yaml` will only exist after plan 01-03 lands. This is expected; no impact on the repo state.
