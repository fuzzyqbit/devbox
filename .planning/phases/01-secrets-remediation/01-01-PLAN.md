3. `ansible/roles/secrets/tasks/generate.yml` — generates the two passwords as in-memory facts. Use the EXACT pattern from RESEARCH.md §1 (lines 152-184), simplified to the local-only path (no SSM publish — that comes in 02-PLAN):
```yaml
---
- name: Generate code-server password (per-build, in-memory only)
  ansible.builtin.set_fact:
    code_server_password: "{{ lookup('ansible.builtin.password',
                                    '/dev/null length=' ~ secrets_code_server_password_length
                                    ~ ' chars=ascii_letters,digits') }}"
  no_log: true

- name: Generate VNC password (per-build, in-memory only)
  ansible.builtin.set_fact:
    desktop_vnc_password: "{{ lookup('ansible.builtin.password',
                                     '/dev/null length=' ~ secrets_vnc_password_length
                                     ~ ' chars=ascii_letters,digits') }}"
  no_log: true

- name: Assert code-server password is non-empty
  ansible.builtin.assert:
    that:
      - code_server_password is defined
      - code_server_password | length >= secrets_code_server_password_length
      - code_server_password != "changeme"
    fail_msg: "code_server_password generation failed or produced a forbidden value"
    quiet: true
  no_log: true

- name: Assert VNC password is non-empty
  ansible.builtin.assert:
    that:
      - desktop_vnc_password is defined
      - desktop_vnc_password | length >= secrets_vnc_password_length
      - desktop_vnc_password != "changeme"
    fail_msg: "desktop_vnc_password generation failed or produced a forbidden value"
    quiet: true
  no_log: true
```

Notes on the snippet above:
- `~` is Jinja string concat; the length is parameterized from defaults so operators can override via `--extra-vars`.
- `chars=ascii_letters,digits` keeps the value shell-safe — no need to quote-escape when piping into `vncpasswd` or rendering into YAML.
- The assert tasks are defense-in-depth: if the lookup ever silently returns an empty string (e.g., misconfigured local fact cache), the play hard-fails BEFORE the empty value reaches a template or systemd unit.
- All four tasks have `no_log: true` per Pitfall 1 (RESEARCH.md:590-598). DO NOT remove it for "debugging" — verify with `-vvv` against a test target and grep the log instead.

Three bugs being fixed (per RESEARCH.md §3 lines 218-253 and CONCERNS.md "creates: guard on VNC password is order-dependent (HIGH)"):

- `echo "..." | vncpasswd` puts the cleartext in `ps` output and the shell history of any user with access during the build.

New content:
```yaml
- name: Set VNC password (rotates per build, no cleartext in process tree)
  ansible.builtin.shell:
    # vncpasswd -f reads cleartext from stdin and writes the obfuscated form to stdout.
    # Use stdin: rather than a shell heredoc so the cleartext never appears in `ps`.
    cmd: "vncpasswd -f > {{ dev_home }}/.vnc/passwd"
    stdin: "{{ desktop_vnc_password }}"
  changed_when: true   # rotation is the intent; declare the change explicitly
  no_log: true
```
