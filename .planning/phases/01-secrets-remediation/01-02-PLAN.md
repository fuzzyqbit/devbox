<objective>
Distribute the per-build secrets generated in 01-PLAN to the running EC2 via AWS SSM Parameter Store with a least-privilege IAM instance profile, and replace the hardcoded `key_name = "me"` with per-operator SSH keys.

Three concurrent workstreams converge here:

1. **Bake-time publish** (Ansible): Extend the `secrets` role created in 01-PLAN with `tasks/publish.yml` that pushes `code_server_password` and `desktop_vnc_password` to SSM as SecureStrings under `/devbox/{{ devbox_user }}/*`. Add `community.aws` to `ansible/requirements.yml`. Plumb `devbox_user` from Packer into Ansible as an extra-var (today it's missing — only `layer_config.yml` is passed).

2. **Boot-time fetch** (Ansible + systemd, baked into the AMI): Add `tasks/install-oneshot.yml` that installs a systemd-oneshot service into the AMI. The service runs on first boot, reads `DevboxUser` via IMDSv2 tag metadata, fetches both SecureStrings via the EC2 instance profile (no static creds), rewrites `~/.config/code-server/config.yaml` and `~/.vnc/passwd`, marks itself complete, and restarts `code-server` + `vncserver` + `novnc`.

3. **Infra-provision** (Terraform + Terragrunt): Add `aws_iam_role.devbox` + `aws_iam_role_policy.devbox_ssm_read` (least-privilege SSM read scoped to `/devbox/${var.devbox_user}/*` with the `kms:ViaService` condition) + `aws_iam_instance_profile.devbox` to `terraform/main.tf`. Wire it into `aws_instance.devbox.iam_instance_profile`. Drop the now-unused `var.iam_instance_profile`. Enable IMDSv2-only with tag-in-metadata. Change `terragrunt.hcl` `key_name` from the literal `"me"` to `"${local.user}-devbox"`. Add a `make secrets-show` target so operators can retrieve their generated values without clicking through the AWS Console.

This plan depends on 01-PLAN landing first because (a) it consumes the `code_server_password` and `desktop_vnc_password` facts created there and (b) it extends `ansible/roles/secrets/tasks/main.yml` to include the new `publish.yml` and `install-oneshot.yml` sub-task files.

Purpose: Close SEC-03 (secret distribution via AWS-managed encrypted store, no static creds on disk) and SEC-04 (per-operator SSH key, documented rotation). Lay the IAM-instance-profile groundwork that Phase 2 (SSM Session Manager option for SSH access) will reuse.

Output: A bootstrap-capable AMI + a Terraform module that grants it least-privilege read access to its own secrets + an operator UX for retrieval. After this plan, the running devbox carries no secret material in user_data, in tfstate, or in the AMI itself — only in encrypted SSM, decryptable only via the per-user instance profile.
</objective>

Insert at line 27 (right after `locals { … }`):
```hcl
# --- IAM: EC2 instance profile for SSM Parameter Store read ---

data "aws_caller_identity" "current" {}
data "aws_region" "current" {}

resource "aws_iam_role" "devbox" {
  name_prefix = "${local.name_prefix}-"
  description = "EC2 role granting ${var.devbox_user}'s devbox read access to its own SSM secrets"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = { Service = "ec2.amazonaws.com" }
      Action    = "sts:AssumeRole"
    }]
  })

  tags = local.common_tags
}

resource "aws_iam_role_policy" "devbox_ssm_read" {
  name = "${local.name_prefix}-ssm-read"
  role = aws_iam_role.devbox.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid    = "ReadOwnSecrets"
        Effect = "Allow"
        Action = [
          "ssm:GetParameter",
          "ssm:GetParameters",
          "ssm:GetParametersByPath",
        ]
        Resource = "arn:aws:ssm:${data.aws_region.current.name}:${data.aws_caller_identity.current.account_id}:parameter/devbox/${var.devbox_user}/*"
      },
      {
        Sid      = "DecryptSecureStrings"
        Effect   = "Allow"
        Action   = ["kms:Decrypt"]
        Resource = "*"
        Condition = {
          StringEquals = {
            "kms:ViaService" = "ssm.${data.aws_region.current.name}.amazonaws.com"
          }
        }
      },
    ]
  })
}

resource "aws_iam_instance_profile" "devbox" {
```

```bash
#!/usr/bin/env bash
set -euo pipefail

# Refuse to run twice. The ConditionPathExists in the unit file is the primary guard;
# this check defends against direct ExecStart invocations.
if [[ -f /var/lib/devbox/secrets-applied ]]; then
    echo "Already bootstrapped (touch /var/lib/devbox/secrets-applied exists); refusing to re-run" >&2
    exit 0
fi

# IMDSv2 session token (required because aws_instance.devbox sets http_tokens=required).
TOKEN=$(curl -fsS -X PUT 'http://169.254.169.254/latest/api/token' \
    -H 'X-aws-ec2-metadata-token-ttl-seconds: 60')

REGION=$(curl -fsS -H "X-aws-ec2-metadata-token: $TOKEN" \
    http://169.254.169.254/latest/meta-data/placement/region)

# DevboxUser tag exposed via tag-in-metadata (aws_instance.devbox metadata_options.instance_metadata_tags=enabled).
DEVBOX_USER=$(curl -fsS -H "X-aws-ec2-metadata-token: $TOKEN" \
    "http://169.254.169.254/latest/meta-data/tags/instance/DevboxUser")

if [[ -z "$DEVBOX_USER" ]]; then
    echo "DevboxUser tag missing in IMDS metadata; refusing to bootstrap" >&2
    exit 1
fi

# Fetch both SecureStrings. AWS CLI v2 uses the instance profile credentials transparently.
CS_PWD=$(aws ssm get-parameter --region "$REGION" \
    --name "/devbox/$DEVBOX_USER/code-server-password" \
    --with-decryption --query 'Parameter.Value' --output text)
VNC_PWD=$(aws ssm get-parameter --region "$REGION" \
    --name "/devbox/$DEVBOX_USER/vnc-password" \
    --with-decryption --query 'Parameter.Value' --output text)

if [[ -z "$CS_PWD" || -z "$VNC_PWD" ]]; then
    echo "Empty password returned from SSM; refusing to write empty config" >&2
    exit 1
fi

# Apply code-server password.
install -d -o ec2-user -g ec2-user -m 0755 /home/ec2-user/.config/code-server
cat > /home/ec2-user/.config/code-server/config.yaml <<EOF
bind-addr: 0.0.0.0:8080
auth: password
password: "$CS_PWD"
cert: true
EOF
chown ec2-user:ec2-user /home/ec2-user/.config/code-server/config.yaml
chmod 0600 /home/ec2-user/.config/code-server/config.yaml

# Apply VNC password. vncpasswd -f reads cleartext from stdin and writes obfuscated bytes to stdout.
install -d -o ec2-user -g ec2-user -m 0755 /home/ec2-user/.vnc
printf '%s' "$VNC_PWD" | sudo -u ec2-user vncpasswd -f > /home/ec2-user/.vnc/passwd
chown ec2-user:ec2-user /home/ec2-user/.vnc/passwd
chmod 0600 /home/ec2-user/.vnc/passwd

# Mark complete BEFORE restarting services. If we mark after, a service-restart failure
# would leave the guard unset and the oneshot would re-fire (and re-rotate ~/.vnc/passwd) on next boot.
install -d -m 0755 /var/lib/devbox
touch /var/lib/devbox/secrets-applied

# Restart dependent services to pick up the new config. Tolerate units that aren't installed
# (novnc may be optional depending on which layers were enabled at bake time).
for svc in code-server.service vncserver.service novnc.service; do
    if systemctl list-unit-files "$svc" >/dev/null 2>&1; then
        systemctl restart "$svc" || echo "WARN: failed to restart $svc" >&2
    fi
done
```

Notes:
- The script uses `set -euo pipefail` and `curl -fsS` so HTTP errors / missing IMDS / empty SSM responses fail loudly. Per security.md "never silently swallow errors".
- `printf '%s' "$VNC_PWD"` (not `echo`) avoids a trailing newline that `vncpasswd -f` would treat as part of the password.
- The `for svc in …; if list-unit-files` loop tolerates a layer-config build where only one of vscode/desktop ran. The bootstrap is enabled unconditionally (next task), but the per-service restart skips missing units gracefully.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator workstation IAM → AWS SSM PutParameter | Operator's identity (the credentials Packer runs under) writes SecureStrings to `/devbox/${devbox_user}/*`. Compromised operator workstation = compromised secrets. Defense: operator's IAM permissions scoped to their own prefix at the AWS account boundary, not by this repo. |
| Bake-time Ansible stdout → Packer terminal | Same as 01-PLAN — `no_log: true` on every SSM publish task. |
| AMI snapshot → many launched EC2s | Anything in the AMI travels to every instance launched from it. The bootstrap unit + script ARE in the AMI; the secrets ARE NOT. The script holds NO credentials, only the AWS CLI invocation that uses the runtime instance profile. |
| EC2 instance profile → AWS IAM → SSM + KMS | Each running devbox can read SecureStrings under `/devbox/${var.devbox_user}/*` and call `kms:Decrypt` only via SSM (kms:ViaService condition). No write access. No cross-user read access. |
| IMDSv2 metadata service → bootstrap script | IMDSv2 session tokens required (http_tokens=required). Container workloads can't reach IMDS (http_put_response_hop_limit=1). |
| SSM Parameter Store API → operator (via `make secrets-show`) | Operator's IAM identity reads via AWS CLI. Same access as PutParameter at bake time (assumed in user_setup). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | Secret in EC2 user_data → readable via IMDS forever | mitigate | NO user_data is set. The bootstrap is a baked-in systemd unit; the secret travels memory-only from SSM → AWS CLI → child process env on the EC2. Per RESEARCH.md Pitfall 2 (lines 600-608). |
| T-02-02 | Elevation of Privilege | Over-broad kms:Decrypt on `*` grants decrypt of ANY SecureString in the account that uses the default `alias/aws/ssm` key | mitigate | Condition `kms:ViaService = "ssm.<region>.amazonaws.com"` pins the decrypt to requests brokered by SSM. RESEARCH.md §5 lines 326-336 + Pitfall 5 lines 630-638. tfsec (Phase 4) will flag any regression. |
| T-02-03 | Information Disclosure | Public-key bytes leak via tfstate if `aws_key_pair` resource is used | mitigate | Per RESEARCH.md §7 line 485, keys are imported OUT OF BAND (`aws ec2 import-key-pair`). The Terraform code only references `var.key_name` (string); tfstate carries only the name. |
| T-02-04 | Spoofing | Two operators with the same `${user}-devbox` keyname clobber each other in AWS | accept (deferred to Phase 4) | RESEARCH.md Pitfall 7 (lines 650-658) acknowledges this. Phase 4 docs pass adds a validation step in CLAUDE.md operator-quickstart. This phase makes the key NAME parametric; uniqueness enforcement is a documentation concern. |
| T-02-05 | Information Disclosure | IMDSv1 caller could read instance metadata without a token, including the now-exposed DevboxUser tag | mitigate | `metadata_options.http_tokens = "required"` rejects IMDSv1. Containers cannot reach IMDS via `http_put_response_hop_limit = 1`. |
| T-02-06 | Elevation of Privilege | Bootstrap script runs as root with broad filesystem write — a malicious DevboxUser tag value could shell-inject | mitigate | DevboxUser is the value of an EC2 tag set by Terraform (`terraform/main.tf:22`) — not a free-form user input. The script uses it only in path interpolation (`/devbox/$DEVBOX_USER/...`) and a curl URL. Defense in depth: the SSM IAM policy is keyed by `var.devbox_user` (Terraform-controlled); an instance with a forged tag could not read another user's parameters. |
| T-02-07 | Denial of Service | Bootstrap fails (SSM unreachable, empty response, etc.) and code-server/vncserver start with the AMI-baked empty/old config | mitigate | systemd unit declares `Before=code-server.service vncserver.service novnc.service`. Script `set -euo pipefail` + empty-value checks → non-zero exit → systemd marks the unit failed → dependent services don't start. The bootstrap's `Wants=network-online.target` ensures network is up before SSM is called. |
| T-02-08 | Tampering | Re-launching an existing EC2 instance re-fetches SSM and rewrites configs unnecessarily | mitigate | `ConditionPathExists=!/var/lib/devbox/secrets-applied` skips on reboot. New instance from same AMI re-runs (good — its SSM values may have been rotated by a re-bake). |
| T-02-09 | Information Disclosure | `make secrets-show` prints both passwords to stdout, which an attacker with a screen-share / scrollback could capture | accept | Trade-off explicitly chosen: operator must retrieve these to use them. Mitigated by short scrollback expectations; not piped to clipboard to keep the dependency surface minimal. Future enhancement (out of scope): copy-to-clipboard via `pbcopy`/`xclip`. |
| T-02-10 | Information Disclosure | tfstate stores resource IDs (including instance profile name) but NOT the IAM policy JSON. Policy JSON is in state. | accept | The IAM policy reveals which SSM path the role can read — operationally useful, no secret material. State file remains in encrypted S3 (verified in terragrunt.hcl:22). |
| T-02-11 | Repudiation | No audit trail of which build wrote which SSM value | mitigate | Every `community.aws.ssm_parameter` PutParameter call emits a CloudTrail event with the caller's identity + timestamp + parameter name. The Ansible task description includes the build timestamp. Out-of-band auditing remains available; this plan adds no new logging code. |
| T-02-12 | Elevation of Privilege | Future contributor adds a wildcard SSM resource ARN to the policy "for convenience" | accept (process control) | tfsec (Phase 4) will flag any `Resource = "*"` on SSM. Code review (security-reviewer agent per agents.md) is the additional control. |
