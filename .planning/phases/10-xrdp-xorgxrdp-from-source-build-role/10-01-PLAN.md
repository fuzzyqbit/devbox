<objective>
Create the `ansible/roles/xrdp/` role that builds and installs the xrdp daemon and the
xorgxrdp Xorg backend modules from vendored, sha256-pinned source at Packer bake time —
entirely against the AL2023 dnf mirror, with no EPEL or third-party repo — and that aborts
the bake with an explicit assertion if the Xorg SDK (or any build dep) is missing.

Purpose: Phase 10 is the BUILD + INSTALL foundation of the v3.2 XRDP milestone. It produces
the binaries/modules that Phase 11 will configure (xrdp.ini/sesman.ini/PAM/systemd) and
Phase 12 will wire to the network. This phase delivers RDP-01 (vendored+pinned source),
RDP-02 (toolchain + Xorg SDK install, then compile+install), and RDP-03 (hard-gate assert).

Output:
- `ansible/roles/xrdp/defaults/main.yml` — pinned versions, sha256 hashes, configurable source base URL
- `ansible/roles/xrdp/tasks/main.yml` — dep install → RDP-03 assert → xrdp build → xorgxrdp build

Scope guard (DO NOT do in this phase): no xrdp.ini/sesman.ini, no PAM file content, no
systemd enable, no playbook.yml wiring, no Terraform/network, no VNC removal. Those are
Phases 11 and 12. The `--with-pam-rules=redhat` configure flag IS passed now (it cannot be
added retroactively after `make install`) but its consumption is Phase 11's concern.
</objective>

<idioms>
<!-- Established repo conventions extracted from the analogs above. Use these verbatim. -->

1. SHA-256 pinned download (devops role, mise):
   get_url with `url:`, `dest:`, `mode: "0644"`, `checksum: "sha256:{{ <var> }}"`.
   The sha256 lives in defaults/main.yml; the task references the var.

2. Pre-build assert (desktop role, leading task):
   `ansible.builtin.assert:` with a `that:` list, a multi-line `fail_msg: >-`, and
   `quiet: true`. Use this to make RDP-03 fail loudly with a human-readable message.

3. Idempotent build step (devtools role, Thrift build — THE analog):
   `command:` with the command string, then an `args:` block carrying `chdir:` and
   `creates:`. NOTE the block form:
     - name: Build X
       command: ./configure --prefix=/usr/local ...
       args:
         chdir: "/tmp/x-{{ x_version }}"
         creates: "/tmp/x-{{ x_version }}/Makefile"
   Use `-j{{ ansible_processor_vcpus | default(2) }}` for make parallelism (devtools idiom).

4. Per-task environment (research Pattern 3):
   `environment:` dict on the xorgxrdp configure task to set PKG_CONFIG_PATH.

5. Tarball extraction (desktop role, noVNC):
   `unarchive:` with `src:`, `dest:`, `remote_src: true`, and
   `extra_opts: ["--strip-components=1"]` to flatten the top-level dir, OR extract to
   /tmp and chdir into the versioned subdir (devtools Thrift pattern). Pick the Thrift
   pattern here since the build chdir's into /tmp/<name>-<version>/.

6. Cleanup: the playbook post_tasks already removes /tmp/*.tar.gz globally; a per-role
   cleanup of the extracted /tmp/<name>-<version>/ source trees is good hygiene (desktop
   role cleans its own /tmp artifacts with `file: state: absent`).
</idioms>

<airgap_decision>
<!-- RDP-01 airgap method — LOCKED for this plan -->
Method: get_url + `checksum: "sha256:{{ ... }}"` from a CONFIGURABLE base URL.

Rationale: This matches the repo's established RDP-01-equivalent convention exactly — the
`devops` role pins `mise` by version + sha256 and downloads via get_url at bake time (the
bake VM has internet to the transport; the sha256 pin is the integrity guarantee). Research
§"Note on vendoring method" confirms this is the correct interpretation of RDP-01 for this
repo (committing 3 MB tarballs into git is the rejected alternative — repo bloat).

Airgap override (MANDATORY, explicit): the download URL is built from a
`xrdp_source_base_url` default var (default the upstream GitHub releases host). An operator
running a true-airgap bake overrides `xrdp_source_base_url` (e.g. via Packer var / group_vars)
to point at an internal mirror that serves the identically-named tarballs. The sha256
`checksum:` pin is enforced regardless of base URL, so a mirror that serves a tampered or
wrong-version tarball fails the bake. This makes the airgap path a one-variable override
with the integrity guarantee preserved.
</airgap_decision>
